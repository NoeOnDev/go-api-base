# Internationalization (i18n)

The API speaks to two audiences, and each has its own language:

| Who | What they see | Language |
|---|---|---|
| **End users** (people using the app in the browser) | Error and validation messages, success messages, emails and notifications | **Theirs**, chosen per request: these texts come from translation catalogs |
| **Developers and operators** | Code, comments, logs, internal errors and command output (`create-admin`, `rotate-keys`) | **Always English**, not translated |

Logs never choose a language: they are written once, in English, like the code. A 500 error shows both sides: the log line says `create note: connection refused`, and the user gets `{"code": "internal_error", "message": "Internal server error."}` in their language.

The template ships with **English (`en`, the default) and Mexican Spanish (`es-MX`, using "tú")**. It is the same idea as Laravel's `lang/` folder and `__('auth.failed')`.

## How the language is chosen

1. Browsers send `Accept-Language` with every request, for example `es-AR,es;q=0.9,en;q=0.8`. A frontend with a language picker can set it explicitly.
2. The API picks the available language that fits best:
   - an exact match first (`es-MX`);
   - otherwise the closest variant of the same language: `es`, `es-AR` or `es-ES` get `es-MX` while there is no catalog of their own;
   - otherwise the default language, `DEFAULT_LOCALE` (`en` if unset).
3. Every response carries `Vary: Accept-Language`, because the same URL can answer in different languages.

**Each user also has a language** (`locale` in the user, `null` = the default language). Emails to the account and live notifications use it, not the language of the request. A security email reaches the owner in their own language, even if the change was made by someone else.
- `POST /auth/register` stores the language the browser asked for, if it is an available one; otherwise `null`.
- `PUT /auth/me` accepts `"locale": "es-MX"` (any letter case). Only available languages are accepted, without falling back to a close one.

## Error responses

Every error has a stable **code** and a **message** in the language of the request:

```json
{"error": {"code": "email_taken", "message": "Este email ya está registrado.", "fields": {"email": "Este email ya está registrado."}}}
```

The code never changes with the language, so the frontend can:
- show `message` (and `fields`) as they come: the simplest option; or
- map `code` to its own texts, if it has its own translations.

The HTTP status is still the usual one (404, 409…), so a generic frontend can rely on it. The complete list of codes is at the end of this page.

## Catalogs

The texts live in `internal/i18n/locales/<locale>.json`, embedded in the binary. Keys are grouped by prefix:

| Prefix | Used for | Example |
|---|---|---|
| `errors.<code>` | The message of each error code | `errors.email_taken` |
| `validation.<rule>` | Per-field validation messages | `validation.too_long` |
| `messages.<name>` | Success messages in responses | `messages.password_reset_sent` |
| `notifications.<kind>` | The text of each notification kind | `notifications.email_changed` |
| `duration.<unit>` | Durations in emails | `duration.hours` |
| `email.<name>` | Texts of the layout of the HTML emails | `email.button_help` |
| `format.<name>` | Go layouts of the dates written for people (see [below](#dates-and-times)) | `format.datetime` |

- `{name}` is filled with an argument: `"Must be at most {max} characters."`.
- A plural text has two forms, `{"one": "1 hour", "other": "{count} hours"}`. Two forms cover English and Spanish; a language with more (like Polish) would need more.
- `en.json` is the reference: every catalog must have exactly its keys. `make check` also fails if the code uses a key that is missing, if a key is no longer used, or if an error code is missing from the table below.
- Validation messages in `es-MX` are written to work for any field ("Este campo es obligatorio."), so they don't depend on the grammatical gender of the field name.

## Adding a language

For example, Argentinian Spanish (with "vos"):

1. Copy `internal/i18n/locales/es-MX.json` as `es-AR.json` and change the texts: `"errors.unauthorized": "Necesitás iniciar sesión."`.
2. Copy `internal/auth/emails/es-MX/` as `internal/auth/emails/es-AR/` and adapt the emails (both files of each one).
3. Run `make check`.

There is no list of languages in the code: the available languages are the catalog files. From then on, a browser in Argentina gets `es-AR`.

To change the tone of a language (for example, "usted" for a formal client), edit its catalog and its emails. The code doesn't change.

## Adding a message

- **An error:** use a code in the handler and add `errors.<code>` to every catalog. For example, `return httpx.Conflict("invoice_already_paid", "")` and `"errors.invoice_already_paid": "The invoice is already paid."`. Add the code to the table below.
- **A validation rule:** return `i18n.M("validation.<rule>", "arg", value)` and add the key. Field messages go in `httpx.Fields`: `fields["title"] = i18n.M("validation.required")`.
- **A success message:** `i18n.FromContext(r.Context()).T("messages.<name>", "arg", value)`.
- **A notification kind:** add `notifications.<kind>`; the values of its `data` fill the placeholders. A kind without a key arrives with an empty `message`, and the frontend builds the text from `kind` and `data`.

Never write a user-facing text in the code: it would always come out in one language.

## Emails

Each language has a folder with the same emails, two files each: `internal/auth/emails/en/password_reset.txt` and `password_reset.html`, `internal/auth/emails/es-MX/password_reset.txt` and `password_reset.html`… The `.txt` is the plain-text version and sets the subject on the first line:

```
{{define "subject"}}Reset your password{{end -}}
Hi {{.Name}},
…
```

The `.html` defines the preview line and the content, which goes inside the shared layout (see "Emails" in [docs/auth.md](auth.md#emails)):

```
{{define "preheader"}}Choose a new password for your account.{{end}}
{{define "content"}}
<h1>Hi {{.Name}},</h1>
<p>…</p>
{{template "button" (button .Link "Choose a new password")}}
{{end}}
```

The texts of the layout (like "if the button doesn't work…") are catalog keys, `email.*`, used with `{{t "email.button_help"}}`. `mail.Templates` (`internal/mail/templates.go`) loads the emails and checks that every language has the same ones, each with both files. Other packages can use it for their own emails.

## Dates and times

A date the API writes for a person (in an email, in a notification) goes in their zone and in their language's format:

```go
tr := catalog.Translator(locale)
tr.FormatDateTime(time.Now().In(loc)) // es-MX: "31/10/2026 00:56 (America/Mexico_City)"; en: "Oct 31, 2026, 12:56 AM (America/Mexico_City)"
tr.FormatDate(day.Start(time.UTC))   // es-MX: "31/10/2026"; en: "Oct 31, 2026"
```

`loc` is the user's zone: `auth.MustUser(ctx).Location()` in a handler (see [time.md](time.md)). The formats are Go layouts (`format.datetime` and `format.date` in the catalogs). Go only writes the names of the months in English, so the other languages use numbers. The dates of the JSON are not formatted: they travel in UTC, and the frontend formats them.

## Notifications

The text of a notification is not stored: the database keeps its `kind` and `data`, and the API builds `message` when it is read, in the language of the reader. The live event (`GET /events`) uses the user's language.

## Limits

- The texts are part of the binary: changing one means deploying again. That is the usual approach for an API, and Laravel works the same way. A project that needs to edit texts without a deploy would move them to the database.
- Dates in emails use a fixed format (`2006-01-02 15:04 UTC`) instead of a per-language one.

## Error codes

| Code | Status | When |
|---|---|---|
| `account_has_data` | 409 | Deleting the account is blocked by data that references it (`ON DELETE RESTRICT`) |
| `account_suspended` | 403 | Login of an account an administrator suspended (only after the right password) |
| `admin_two_factor_required` | 403 | `REQUIRE_ADMIN_TWO_FACTOR=true` and the administrator has not turned on 2FA |
| `appointment_not_found` | 404 | The appointment does not exist, or belongs to someone else (example `appointments`) |
| `branch_exception_not_found` | 404 | Deleting the exception of a date that has none (example `branches`) |
| `branch_in_use` | 409 | Deleting a branch that has appointments (example `branches`) |
| `branch_not_found` | 404 | The branch does not exist (example `branches`) |
| `category_in_use` | 409 | Deleting a category that has products |
| `category_not_found` | 404 | The category does not exist |
| `cross_origin_rejected` | 403 | A browser sent a request that modifies data from another site (CSRF) |
| `email_not_verified` | 403 | `REQUIRE_EMAIL_VERIFICATION=true` and the email is not confirmed |
| `email_taken` | 409 | Registering, or changing the email, to an email that already has an account |
| `empty_body` | 400 | The request body is empty |
| `forbidden` | 403 | The route is for administrators only |
| `internal_error` | 500 | Unexpected error (the cause is in the log, with the `request_id`) |
| `invalid_credentials` | 401 | Wrong email or password in the login |
| `invalid_path_id` | 400 | An `{id}` in the path is not a positive whole number |
| `invitation_accepted` | 409 | Sending the invitation again to a user who already accepted it |
| `last_admin` | 409 | Deleting the only administrator account |
| `malformed_json` | 400 | The request body is not valid JSON |
| `multiple_json_values` | 400 | The body has more than one JSON value |
| `note_not_found` | 404 | The note does not exist, or belongs to someone else |
| `notification_not_found` | 404 | The notification does not exist, or belongs to someone else |
| `own_account` | 409 | An administrator tries to change the role of, suspend or delete their own account from `/admin/users` |
| `payload_too_large` | 413 | The request body exceeds 1 MB |
| `product_not_found` | 404 | The product does not exist |
| `route_not_found` | 404 | No route matches the method and path |
| `session_not_found` | 404 | Closing a session that does not exist, or belongs to someone else |
| `shutting_down` | 503 | Opening `GET /events` while the API is shutting down |
| `slot_taken` | 409 | Someone else booked that time first (example `appointments`) |
| `slug_taken` | 409 | Another category or product already uses the slug |
| `too_many_connections` | 429 | Too many open `GET /events` connections (per user or in total) |
| `too_many_emails` | 429 | The user asked for more emails than allowed (resending the verification, changing the email) |
| `too_many_requests` | 429 | A rate limit was exceeded (see `Retry-After`) |
| `too_many_topics` | 400 | `GET /events?topics=` asks for more than 20 topics |
| `two_factor_already_enabled` | 409 | Enabling two-factor authentication when it is already on |
| `two_factor_challenge_expired` | 401 | The second step of the login expired or was already used |
| `two_factor_locked` | 401 | Too many wrong codes in the second step: the login starts over |
| `two_factor_not_enabled` | 409 | Disabling two-factor authentication, or regenerating its codes, when it is off |
| `two_factor_secret_changed` | 409 | The QR code changed (another `setup`) while it was being enabled |
| `two_factor_setup_required` | 409 | Enabling two-factor authentication without asking for the QR code first |
| `two_factor_unavailable` | 503 | The two-factor secret cannot be decrypted (an `ENCRYPTION_KEY` problem) |
| `unauthorized` | 401 | The route needs a session, and there is none (or it expired) |
| `unavailable` | 503 | `GET /healthz`: the database is not responding |
| `unknown_field` | 400 | The body has a field the route does not accept |
| `unreadable_body` | 400 | The request body could not be read |
| `user_not_found` | 404 | The user does not exist (`/admin/users/{id}`) |
| `validation_failed` | 422 | Some fields are not valid: see `fields` |
| `wrong_body_type` | 400 | The body is valid JSON of the wrong type (for example, a list instead of an object) |
| `wrong_type` | 400 | A field has the wrong type (for example, text instead of a number) |
